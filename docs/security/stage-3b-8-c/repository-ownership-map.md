## Relevant routes and route registration

Current `main.py` registers only `security_router` and `organizations_router`
(`main.py:40-42`). It defines customer, overview, memory, signal, insight,
autopilot and WebSocket routes (`main.py:105-234`); business handlers have no
authorization dependency and global/customer queries lack organization
scoping. The identity and membership routers do not automatically secure them.

`backend/routes/events.py`, `backend/routes/insights.py`, and
`backend/routes/billing.py` define routes but are not registered by this
entrypoint. Do not conclude those routes are deployed or exposed. The Express
source mounts its intelligence and replay routers at `src/server.ts:14-20`;
actual deployment exposure remains unknown.

## Source facts versus unknown state

- **Repository declarations:** migrations and source contain the fields,
  constraints, policies, and query patterns cited above.
- **Observed source behavior:** listed handlers issue global or ID/user/context
  queries without verified organization scope where noted.
- **Founder-approved logical requirements:** contract in
  [ownership-contract.md](./ownership-contract.md).
- **Unknown:** deployed table definitions, migration history, row contents,
  ownership quality, effective grants/RLS, and production route exposure.

No record ownership may be inferred from email, domain, user ID, event ID,
context ID, timestamps, or a caller-selected organization.
