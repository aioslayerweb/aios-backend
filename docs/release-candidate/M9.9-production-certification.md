## Known Issues
- Lighthouse scores were not measured in-browser during this session.
- Cross-browser manual testing was not executed here.
- GA4 (`NEXT_PUBLIC_GA4_ID`) and PostHog (`NEXT_PUBLIC_POSTHOG_KEY`, with optional `NEXT_PUBLIC_POSTHOG_HOST`) are optional and require their respective environment variables. Microsoft Clarity is intentionally not initialized: it records session content and URLs, and this application does not currently enforce a suitable masking policy or separate replay consent. No analytics preference or jurisdiction-specific consent policy has been approved in this release checklist; product and privacy owners must confirm the production policy.

## Analytics Privacy Controls
- The site stores an explicit `granted` or `denied` analytics preference in browser local storage; no choice means analytics stays disabled.
- Visitors can change the choice using the persistent Privacy settings control. If browser storage is unavailable, analytics remains disabled until the visitor explicitly opts in during that visit.
- Google Analytics events use broad area-only page locations, disable ad signals, and disable automatic initial page views. Production owners must inspect the GA4 web stream's **Enhanced measurement** settings: disable Page views (including history-based page changes), Outbound clicks, and any other enabled measurement event not explicitly approved. Review Site search, Scrolls, File downloads, Video engagement, and Form interactions individually. `send_page_view: false` in this code does not verify or disable those property-level settings, and repository access cannot establish their production state. PostHog disables autocapture, page views, and session recording, and sanitizes outgoing event properties. Clarity session replay remains disabled pending a separate privacy review.
- Provider script loading and event tracking are gated by the explicit choice. This implementation is a technical privacy control, not a claim of legal compliance.
