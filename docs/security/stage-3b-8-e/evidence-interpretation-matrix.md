## Interpretation rules

1. Record facts as **visible in repository**, **visible in approved database
   metadata**, or **unknown**. Never combine these categories.
2. A missing result may mean absent object, limited visibility, wrong schema,
   or query scope omission. Do not convert it into a negative security claim.
3. Database metadata can establish structure and visible policy/grant
   declarations, not historical business ownership or correct event meaning.
4. Never treat a user-selected organization, user ID, email, customer/event ID,
   context ID, or timestamp as ownership proof.
5. Do not recommend tenant access for unowned or unknown-classification records.
